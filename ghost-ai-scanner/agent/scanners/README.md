# agent/scanners/

Vendored companion tools, built independently under `D:\giggso_intern\Patron
features` and grafted here whole. Each is a standalone, stdlib-only Python
package with its own `pyproject.toml`, README, design-rationale doc, and test
suite — untouched except for provenance headers. Modelled on `agent/capture/`
(commit `f010d07`), the existing precedent for shipping a real multi-file
Python package to the endpoint fleet as an installer companion.

`MCP Searcher` is **not** vendored here — its host parsers and runtime
correlation were ported directly into the existing
`agent/install/scan_mcp_configs.py.frag`, which already owns the `mcp_server`
finding type and the `pipeline_mcp_change.py` flip-detection contract. See
that fragment's audit log for what was ported and why.

## What was deliberately left behind on copy

- `.venv/`, `__pycache__/`, `.mypy_cache/`, `.pytest_cache/`, `.ruff_cache/`,
  `.coverage` — build/tool caches, not source.
- `.git/` — each upstream folder had its own 1–5 commit local history with no
  remote; not worth a subtree merge. Provenance lives in this file instead.
- `.raven/` — **excluded from every package.** `Extension Searcher/.raven/manifest.secrets.json`
  contained a live-looking RavenHub bearer token. It was never committed here
  and never should be.
- `*.egg-info/` — regenerated by `pip install -e`, not source.
- `.apikey-scanner/findings.db` (apikey-scanner) — a SQLite database naming
  the exact file and line of every secret found on the machine that produced
  it. Never vendor a populated one; see the endpoint-adapter note below.
- `scan.json` (extension-searcher, mcp-searcher) — a stale local run's output,
  not a fixture.

## How these run

On the endpoint agent, nothing here is installed via `pip`. Following the
capture-companion pattern, source files are read at installer-render time
by `scripts/render_agent_package.py`, base64-packed, and unpacked on the
target device — no PyPI, no network install step, no version drift between
what the installer bundles and what runs. A ~50-line adapter fragment per
tool shells out to it (`python -m <pkg> --format json`) and maps its records
onto ordinary PatronAI finding dicts. See:

- `agent/install/scan_declared_deps.py.frag` (AI-SDK-Scanner adapter)
- `agent/install/scan_browser_extensions.py.frag` (Extension Searcher adapter)
- `agent/install/scan_hardcoded_secrets.py.frag` (apikey-scanner adapter)

For local development and the host repo's own pytest run, `tests/vendor/conftest.py`
puts each package directory on `sys.path` so the original test suites run
unmodified against the vendored copy — no editable install required there
either.

## Two design invariants preserved from upstream, enforced at the adapter boundary

**No severity, no verdict, inside the vendored code.** Both AI-SDK-Scanner
and apikey-scanner state — in their own design docs, not incidentally — that
having no severity field and no fail-on-found flag is a hard constraint:
"findings are evidence... not a judgment." PatronAI's matcher takes the
opposite position: every event gets a verdict, nothing passes silently. Both
are correct in their own layer. Severity assignment happens **only** in the
adapter fragment and in `src/normalizer/agent_explode.py`'s
`_FINDING_SEVERITY` table — never inside `ai_sdk_scanner/`, `apikey_scanner/`,
or `extension_searcher/` themselves. Do not add one there.

**Redact-then-drop, re-applied at the boundary.** Each tool has its own
redaction. PatronAI's contract is stricter and non-negotiable: any string
that still matches the secret regex *after* redaction is dropped from the
finding entirely rather than shipped half-clean (see
`agent/install/scan_redactor.py.frag`). Every adapter fragment re-runs
`_redact_text()` over every string field it emits, unconditionally, even
though the vendored tool already redacted. This is deliberate belt-and-braces,
not redundancy to clean up.

## Ephemeral by default

`apikey-scanner`'s own README calls its findings database "a precise map an
attacker would want" — true for one machine, worse multiplied across a
fleet. The endpoint adapter runs it in a stateless, `--no-store` mode: scan,
emit, exit, no `.apikey-scanner/` directory left behind. If diff-across-scans
is ever needed on-device, that decision needs its own review — don't turn
persistence back on by default to make an adapter simpler to write.
